# 포털을 React + TypeScript + Vite로 전환

## 문제

앱마다 폴더 구조와 명령이 제각각이라 Bumm님이 로컬에서 손대기 어렵다. 어떤 앱은
빌드가 있고 어떤 앱은 없고, 실행·테스트 명령도 저장소마다 다르다. 8개 앱을
`npm run dev` / `build` / `test`로 통일하기 위한 전환이고, portal은 그중 하나다
(Calculator만 제외).

portal은 특히 빌드가 아예 없어서 사이트 전체가 `public/index.html` 한 파일(1,453줄:
CSS 528 + 마크업 293 + 인라인 스크립트 582)에 들어 있었다. 그 한 덩어리 안에서
구조적 문제도 같이 자라 있었다:

- CSS가 **소스 순서에 의존**했다. 모바일 전용 규칙이 "베이스 규칙보다 파일에서 뒤에
  있어야 이긴다"는 성질에 기대어 특정 위치에 끼워져 있었고, 그 위치를 잘못 잡아
  규칙이 조용히 무시되는 사고가 두 번 났다(`.app`/`.player-mobile`, `.desc .short`).
  "왜 여기에 두는지"를 설명하는 메타 주석이 규칙과 떨어진 곳에 쌓여 있었다.
- 데스크탑/모바일 플레이어의 DOM 참조를 손으로 짝지어 배열로 들고 다녔다(배선 55줄).
  짝짓기를 빠뜨려 모바일만 갱신이 안 되는 버그가 실제로 있었다.
- 같은 SVG 아이콘이 데스크탑용·모바일용으로 두 벌씩 박혀 있었다(path 26개 중 고유
  13개). 한쪽만 고치고 짝을 놓치는 사고가 가능한 구조였다.

## 원하는 결과

- `npm run dev` / `npm run build` / `npm test` / `npm run lint` 네 명령으로 다른 앱과
  동일하게 다룰 수 있다.
- **화면과 조작감이 전환 전과 동일하다.** 레이아웃·색뿐 아니라 애니메이션 길이,
  이징, 스크롤 감각, 전환 타이밍, hover/focus/tap 피드백, 반응 지연까지 포함한다.
- 위 세 가지 구조적 문제가 **재발 불가능한 형태로** 없어진다 — 규칙을 문서에 적어
  두는 것이 아니라, 구조 자체가 그 실수를 허용하지 않아야 한다.
- 배포 대상이 `public/` → `dist/`로 바뀌고, CI가 빌드까지 포함해 게이트를 건다.

## 영향받는 사용자·시스템

- **실사용자(학생·교사)의 화면에 직접 영향**을 준다. 전시·행사에서 쓰는 포털이라
  화면이 달라지면 바로 드러난다.
- **배포 파이프라인이 바뀐다.** `firebase.json`의 배포 대상, GitHub Actions 워크플로
  6개, 배포 전 게이트 스크립트가 전부 영향을 받는다.
- 저장소는 이것 하나지만, 카드가 가리키는 앱 6개는 **건드리지 않는다**(포털은 링크만
  건다).
- 되돌리기가 번거롭다 — 되돌릴 지점은 태그 `portal-freeze-20260908-pre-react`.

## 제약

지킬 수 없다는 걸 발견하면 완화하지 말고 멈추고 보고한다.

- **UI/UX가 체감까지 동일해야 한다.** "언어를 바꿨으니 이렇게밖에 안 된다",
  "누더기를 뜯다 보니 이렇게 됐다", "일단 이렇게 하고 나중에 다듬겠다"는 사유로
  인정되지 않는다. 소스가 누더기인 것과 화면이 누더기인 것은 별개다 — 렌더 시점에는
  속성마다 이긴 규칙 하나만 화면에 나타나므로, **최종 계산값(computed style)만 정확히
  재현하면 화면은 그대로다.** 구조를 깔끔하게 하는 것과 결과가 같은 것이 충돌하는
  것처럼 보이면 **결과가 이긴다.**
- **동일함은 바이트 복사가 아니라 테스트로 증명한다.** 4개 뷰포트(1600/1180/560/390)
  스크린샷 비교와, LOCKED 설계 결정을 수치로 단언하는 테스트 둘 다 통과해야 한다.
  눈대중으로 "비슷하게"는 실패다.
- **DOM의 id·class를 현행과 동일하게 유지한다.** 그래야 기존 Playwright 테스트가
  수정 없이 그대로 회귀 감시망이 된다.
- **주석을 감축하지 않는다.** 인라인 스크립트의 주석 94줄은 장식이 아니라 과거
  실사고의 원인과 기각된 대안 기록이다(자동재생 폴백이 카드 탭에 걸린 사고,
  `lastVolume`이 1로 남아 최대음량으로 튀던 버그, `requestAnimationFrame` 대신
  `setInterval`을 쓴 이유, 플레이어 높이를 1행에 맞췄다가 잘린 건). 새 구조에서 그
  로직이 간 위치로 **전량 이관**한다.
- **보류된 기능은 지우지 않는다.** 셔플 분기는 곡이 1개라 지금은 무동작이지만
  "곡이 늘면 그대로 동작하도록 미리 연결해둔" 문서화된 확장점이다 — 조건
  `PLAYLIST.length > 1`을 그대로 두고 의도 주석도 함께 옮긴다. 가사 데이터의 빈 줄
  14개(간주 스크롤 속도 조절), `lastVolume`의 이중 기본값(버그 수정 흔적)도 보존한다.
- **찌꺼기는 누가 썼는지와 무관하게 걷어낸다.** 판정 기준: 지웠을 때 사용자가 관찰할
  수 있는 변화가 없으면 지우고, 대표가 고른 값·보류한 기능을 담고 있으면 남긴다.
- **줄 번호로 참조하는 주석을 만들지 않는다.** 기존 코드에 있던 두 곳(`1307`,
  `1328`)은 코드가 자라며 이미 엉뚱한 줄을 가리키고 있었다 — 이름으로 참조한다.
- **임시방편을 남기지 않는다.** "일단 동작하게", "차선책으로", "우회로", "나중에
  제대로"는 없다. 지금 제대로 할 수 없으면 어설픈 걸 만들어 놓고 넘어가지 말고
  멈추고 보고한다. 코드에 `TODO`/`FIXME`/`임시`/`나중에`를 남기지 않는다.
- **CLAUDE.md의 LOCKED 항목을 되돌리지 않는다** — 카드 DOM 순서, 데스크탑 3열x2행 열
  우선 채우기, 플레이어-그리드 이음매가 페이지 중심선과 일치, 반딧불이 200개, 번호
  뱃지 제거 상태, 앱 링크는 전부 새 탭.
- **SRI를 다시 시도하지 않는다**(과거 라이브 폰트 로드 전면 차단 장애).

## 미결 질문

- **`.player-bg`(블러 앨범아트 배경)를 실제로 살릴 것인가.** 전환 중에 이 요소가
  뒤따르는 `.player > *` 규칙에 덮여 `position: relative`·폭 0으로 렌더되고 있었음을
  실측으로 확인했다. 즉 **의도했던 블러 배경은 라이브에서 한 번도 보인 적이 없고**,
  대신 flex 항목 자리를 차지해 34px 간격을 만들어 왼쪽 열을 밀어내고 있었다. 지금은
  겉모습을 그대로 두기 위해 그려지지 않던 요소를 지우고 그 간격만 명시했다. 원래
  의도대로 배경을 켜면 플레이어의 인상이 바뀌므로 **대표 판단 사항**이며, 임의로
  켜지 않았다.

그 외 미결 질문은 없다. 아래는 이미 답이 난 것들이라 위 "제약"에 반영했다:
셔플 분기 보존(확장점이므로 유지), 훅 3분할, 가사 스크롤을 state가 아니라 ref로
직접 갱신(초당 25회 리렌더 방지), CSS를 컴포넌트별 소유 구조로 다시 짜기(순서 의존
제거), CSP를 `script-src 'self'`로 단순화하고 검사 대상을 "인라인 script가 없을 것"
으로 바꾸기, 폰트 커버리지를 렌더된 DOM 기준으로 다시 짜기, 404를 빌드 단계에서
복사하기.
