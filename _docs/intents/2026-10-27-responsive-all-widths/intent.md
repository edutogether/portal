# 모든 화면을 모바일부터 2560까지 반응형으로 맞춘다

## 문제

데스크탑 레이아웃의 글자·여백·아이콘이 고정 px라서, 1280px에서는 카드 글자가 빽빽하게 줄바꿈되고
2560px에서는 내용이 작게 가운데에 몰려 양옆이 비어 보인다. 터치 기기에서는 16~19px 아이콘 버튼과
3px 슬라이더가 손가락으로 누르기 어렵다. 하단 고정 플레이어가 맨 아래 푸터를 가린다.
(2026-10-27 대표 지시, 팀장 경유.)

## 원하는 결과

360 · 390 · 430 · 768 · 1024 · 1280 · 1366 · 1440 · 1920 · 2560px 열 폭 모두에서 가로 스크롤·겹침·잘림·
지나친 빈 공간·너무 작거나 큰 글자가 없다. 크기는 폭마다 손으로 맞추지 않고 비율로 커지고 작아진다.
수정 전·후 캡처를 화면 5개 × 폭 10개로 남긴다.

## 영향받는 사용자·시스템

- 모든 방문자의 화면 배치와 크기(색·글꼴·문구는 그대로). 이 저장소만 건드린다.

## 제약

- LOCKED 항목은 그대로: 새 탭 링크, 카드 DOM 순서·그리드(>1180px 3열x2행 열 우선, ≤1180px 2열, ≤560px 1열),
  플레이어 높이 = 카드 위쪽 2행, 이음매 = 페이지 중심선, 소리·볼륨 사양, 파비콘, 로딩 두 바퀴·상한 8초.
- 1600px 폭의 데스크탑 값은 수정 전과 같아야 한다(`tests/locked-geometry.spec.js`가 지킨다).
- 화면 비율을 고정해 통째로 늘리는 방식(zoom·transform scale)은 쓰지 않는다.
- 라이브 배포 없음 — 캡처를 대표가 본 뒤 팀장 확인을 거쳐 배포한다. GitHub 푸시·`gh`는 계정 정지로 쓰지 않는다(커밋은 로컬만).

## 접근

- `base.css`에 단위 `--u`(상자)·`--t`(글자)를 둔다. 1181px 이상에서 `clamp(하한, 100vw/1600, 1.6px)`이라 1600px에서 1px이고
  폭에 비례한다. 글자는 하한을 0.9로 높여 1280px에서도 너무 작아지지 않게 한다. 데스크탑 CSS의 px를 이 단위의 배수로 바꾼다.
- 터치(`pointer: coarse`)에서만 버튼 칸을 36px 이상, 슬라이더 입력 칸을 28px로 키운다(눈에 보이는 모양은 그대로).
- 하단 바 높이만큼 푸터 아래를 비운다. 한글은 어절 단위로 줄을 바꾼다.
